## 1. 阻断发现

### [P1] 辅助接口失败会把整个应用误报为“本地 API 未连接”

`web/src/App.tsx:54-75` 使用一个 `Promise.all` 同时读取 dashboard、sources、experts、runs、feedback、settings 和 configuration-status。任何一个辅助接口失败都会进入统一 `catch`，清空部分成功结果的可见性并显示全局连接错误。

这与 UI 执行文档“部分失败时保留可用内容并明确缺失项”的状态契约不一致，也使局部仓储/API 故障无法与真正的服务不可达区分。现有测试覆盖 dashboard 自身的 `data_complete=false`，但未覆盖七个首屏请求中仅一个失败的情况。

验收要求：按页面关键数据与辅助数据拆分请求结果，使用 `Promise.allSettled` 或独立加载状态；仅 dashboard/基础服务真正不可用时显示全局错误，其余情况显示 partial 状态并保留已成功内容；补充至少一个辅助接口失败、其他接口成功的组件或浏览器用例。

### [P1] 回收站读取失败被伪装为空态，恢复/永久删除失败没有可见反馈

`web/src/App.tsx:234-251` 将回收站请求异常直接转换为空数组，因此网络或服务端错误会显示“回收站为空”。恢复与永久删除写操作只有成功链，没有 pending、防重复、catch 或重试提示；失败时用户无法判断操作是否生效。

这直接违反 UI 执行文档中的“服务端错误不可伪装为成功/空态”以及 mutation 的 pending、失败保留与可重试约束。当前浏览器 E2E 只覆盖两个成功闭环，没有覆盖失败分支。

验收要求：回收站增加 loading/error/empty/success 独立状态；恢复与永久删除增加 pending、防重复和错误提示；失败后保留原记录并允许重试；增加读取失败、恢复失败、永久删除失败测试。

当前版本可以作为**本地产品验收候选**继续修正，但不能认定为“项目整体完成”或“可正式发布”：
