## 1. 交付结论

已补齐评审报告指出的核心页面、关键展示内容及预设交互状态，可进入产品布局与交互方式确认。此结论不等同于 PRD 全部功能、真实数据或实现期验收通过。

## 3. 统一的产品契约

1. 四专题：大模型与智能体、AI 产品形态与行业应用、AI 产品实战、AI 工程安全与可靠性。
2. 默认五维权重：来源权威性30%、及时性25%、传播范围15%、信息密度15%、创新性15%。
3. 默认达标阈值70，每日最多50条，必读/重要/扩展按10/20/20分层；不足不凑数。
4. 扫描窗口为连续7×24小时；定时23:00是本次原型的示例配置值。
5. 系统归档只读；笔记、收藏、置顶、阅读状态独立。
6. 来源覆盖比例表示采用该观点的来源占比，不是事实置信度。
7. 扩展结果先临时展示，收藏后去重入库或关联已有事件。
8. 反馈提交不会自动修改评分；明确确认后启用新版本；旧配置和历史评分保留。
9. 来源删除为逻辑删除，历史档案保留；情报彻底删除需二次确认且不可恢复。不增加未经 PRD 要求的“30天自动清空”规则。
10. 服务页面仅表达已配置/未配置等状态，不展示密钥。

## 4. 建议走查的六条流程

| 流程 | 从哪里开始 | 建议检查点 |
| --- | --- | --- |
| 精读与追溯 | 今日情报 → 第一条详情 | 正文/译文分区 → 来源及覆盖比例 → 版本时间线 → 选题建议 |
| 扩展与入库 | 详情 → 扩展搜索 | 临时结果 → 收藏确认 → 正式档案；另走重复关联及失败重试分支 |
| 反馈与评分 | 质量反馈 → 发起评分校准 | 建议未生效 → 确认/拒绝 → 版本历史 → 回退 → 重评分 |
| 来源与运营 | 来源管理 | 表单校验 → 保存；暂停/恢复/逻辑删除；专家及 GitHub 设置 |
| 故障恢复 | 运行记录 → 失败详情 | 明确失败阶段 → 局部重试；飞书仅重发失败分段；重复任务拒绝 |
| 剔除与恢复 | 详情 → 剔除情报 | 必选原因 → 剔除后有效列表变化 → 回收站恢复；另走彻底删除 |

通过页头“原型导览”可返回总入口；通过“状态验收”可直接进入空数据、未完成、检索降级、笔记保存失败等边界场景。

## 5. 设计方式与使用边界

- 桌面视口为1440×1000，固定侧导航，主内容区域可纵向滚动。
- 为便于确认长正文和多来源信息层级，v2 采用独立详情页与可切换标签。确认/结果步骤也以独立状态页表达；不是已定稿的抽屉或弹窗动效方案。
- 表单通过预设值和结果页演示布局、校验、保存、取消，不支持任意输入、真实下拉选择或拖拽排序。专题顺序通过“移至第一位 → 预览 → 保存”演示。
- 收藏、阅读、回收站等使用预设快照，不是跨所有导航路径共享的全局可变数据。重新从导航进入某个基线场景，会看到该场景的基线数据；不能据此验证刷新持久化。
- 主要精读样本提供完整详情结构；其他列表事件提供与标题、专题、分数对应的精简正文样例，用来验证路由不串错事件。
- 数据、来源、日期、错误日志及校准试算为演示样例。example.com 是明确标注的占位来源；原始来源入口进入说明页，不冒充已核验网页。
- 异步操作通过“查看结果/失败状态”等按钮切换预设结果，不执行真实采集、模型生成、发送或删除。

产品确认应聚焦信息层级、主页面布局、操作顺序、反馈文案和分支是否符合预期。自由输入控件、全局状态联动、持久化以及外部服务联调属于后续实现任务。
