# AI 情报知识库 Figma UI / PRD 验收评审报告

- 评审日期：2026-09-05
- PRD 基线：`AI情报知识库_PRD_工作稿.md`，当前版本 v3.0
- Figma 文件：[AI情报知识库 · 功能布局与交互原型 v1](https://www.figma.com/design/PjXzkYaVIX4BxV26eW1Tk6)
- 评审对象：1 个说明页、8 个主页面、1 个情报详情状态、2 个危险操作确认状态
- 评审方式：PRD 功能、展示、交互及异常验收项与 Figma 画面、关键控件、原型连线逐项映射
- 总体结论：**不通过；可作为信息架构与视觉方向初稿，不建议直接作为下一轮迭代开发的唯一 UI 基线。**

## 1. 执行摘要

当前原型完成了 PC 端整体框架、8 个一级导航页面、统一视觉语言，以及“情报详情 → 填写剔除原因 → 回收站”和“回收站 → 永久删除二次确认”两条危险操作路径。Figma 已设置从“今日情报”开始的 Flow，主导航互通，画面结构清晰。

但 PRD 的核心价值闭环是“来源管理 → 采集与处理 → 精读与检索 → 选题转化 → 质量反馈与人工校准”。当前原型主要覆盖浏览骨架，未完整覆盖来源配置、事件版本、多来源证据、扩展搜索结果收藏入库、评分校准确认与回退、失败任务阶段级重试等核心操作。

本次检查到 12 个顶层画面、81 个带原型连线的节点、0 个 Figma Component / Component Set / Instance。画面数量本身并非问题；关键问题是多个按钮和标签只有视觉形态，没有目标状态或交互连线。

## 2. 结论分级

| 维度 | 结论 | 说明 |
| --- | --- | --- |
| 信息架构 | **部分通过** | 8 个主入口齐备，但专题分类口径与 PRD v3.0 不一致。 |
| 页面覆盖 | **不通过** | 缺少扩展搜索结果、评分校准、失败运行详情、来源编辑等关键页面或状态。 |
| 核心组件 | **不通过** | 多个关键控件只有静态外观；缺少版本切换、来源证据表、校准建议卡、失败阶段卡等组件。 |
| 主流程闭环 | **不通过** | 浏览和删除路径部分闭环；来源配置、搜索、收藏/置顶、恢复、校准、重试均未闭环。 |
| 异常与边界状态 | **不通过** | 缺少空数据、数据不完整、处理中、来源不可访问、扩展搜索失败、配置缺失等状态。 |
| 视觉一致性 | **通过（原型级）** | 1440×900 桌面框架、颜色、层级和表格风格基本统一，可读性良好。 |
| 交付可维护性 | **部分通过** | 图层有语义命名，但没有复用组件和组件状态，后续改版成本较高。 |

## 3. P0 阻断问题

### P0-01：四个一级专题与 PRD v3.0 不一致

PRD 规定四个一级专题为：

1. 大模型与智能体；
2. AI 产品形态与行业应用；
3. AI 产品实战；
4. AI 工程安全与可靠性。

当前 Figma 使用的是“AI 产品与模型、AI 工程安全与可靠性、AI 开发工具与平台、AI 行业与产品实践”。其中“AI 开发工具与平台”被提升为一级专题，“产品形态与行业应用”和“产品实战”被合并，属于数据分类、导航入口、统计口径和推送顺序的基础契约不一致。

影响范围：今日首页专题统计、专题档案、历史筛选、来源归类、系统设置中的专题顺序、飞书推送顺序。

验收要求：先确认是否修改 PRD；若 PRD 不变，Figma 全部页面必须统一为 PRD 的四个专题名称和顺序。

### P0-02：情报详情尚未满足“可精读、可追溯、可看版本”的核心要求

当前详情抽屉已包含只读标识、中文摘要、简要观点、评分说明、个人备注、选题提示和剔除入口，但存在以下缺口：

- “来源与观点”“版本记录”仅是静态标签，没有可切换内容；
- 未展示首次版本、最新版本、版本时间线和版本差异；
- 多来源区域缺少来源名称、原始链接、发布时间及来源覆盖比例；
- 英文内容只有一段英文说明，未明确拆分“英文原文、中文译文、中文摘要”；
- 评分解释展示 4 个维度，且维度口径与 PRD 的“来源权威性、及时性、传播范围、信息密度、创新性”不一致；
- 未显示评分配置版本；
- 缺少跳转原始来源入口；
- 选题建议只有标题提示，缺少内容大纲、核心爆点、支撑来源及手动生成动作；
- 缺少“置顶”操作。

对应 PRD：F3、F4、F6、F8、F10、F12，以及 AC-F08～F11、AC-F16、AC-F24、AC-D06～D10。

验收要求：新增至少 4 个详情状态——归档正文、多来源观点、版本时间线、选题建议；补齐上述字段和可点击切换。

### P0-03：质量反馈未形成“反馈 → 校准建议 → 用户确认 → 新评分版本 → 回退”的闭环

当前质量反馈页只支持静态展示反馈清单、选择反馈类型和填写说明。PRD 明确要求：

- 用户手动发起评分校准；
- 展示反馈样本量、不确定性、调整建议、影响维度和预计影响范围；
- 用户确认后才能启用新评分版本；
- 支持拒绝建议、查看历史评分版本、回退版本和手动重新评分历史情报；
- 反馈提交本身不得自动改变评分配置。

当前原型没有校准入口、建议审核页、确认态、评分版本历史或回退状态；反馈筛选、详情和保存按钮也没有原型连线。

对应 PRD：F7、AC-I09～I13、状态原则 5.2/5.3。

验收要求：新增“评分校准工作台”“校准建议确认”“评分版本历史/回退确认”“历史情报重新评分范围确认”四类状态。

### P0-04：扩展搜索只有入口文案，没有结果与收藏入库闭环

详情页显示“扩展检索 →”，但控件没有原型连线，也没有扩展搜索加载、结果、失败、重试、重复关联或收藏入库页面。

PRD 要求扩展结果先进行质量检查并临时展示，只有收藏后才能去重并进入正式档案；与已有档案重复时应关联原事件；搜索失败时原情报不变并允许重试。

对应 PRD：F11、AC-F26、AC-I15、AC-E12，以及内容边界 5.1。

验收要求：新增“搜索中、结果列表、无结果、失败可重试、重复事件关联、收藏并归档成功”至少 6 个状态。

## 4. P1 关键缺口

### P1-01：来源管理仅有列表，没有管理流程

已有：信息源表、专家白名单表、状态和截断长度示例。

缺少：

- 新增/编辑来源表单及字段校验；
- 来源地址、最近采集时间、最后结果和失败原因；
- 暂停、恢复、逻辑删除确认与操作结果；
- 专家白名单新增、编辑、移除流程；
- GitHub 日榜、周榜、近 7 天 Star 增长、AI 相关性及项目白名单配置；
- 视频/播客来源配置；
- 来源级采集规则与正文截断长度配置状态。

“新增来源”按钮和表格操作均未连线。对应 F1、AC-F01～F03、AC-I14。

### P1-02：系统设置覆盖范围不足且标签页不可操作

当前只展示时区、每日运行时间、采集窗口、单源候选数和两个开关。以下 PRD 必填配置缺失：

- 必读/重要/扩展分层数量；
- 评分阈值及五维权重；
- 专题显示顺序；
- 默认排序方式；
- 飞书配置状态及大模型服务配置状态；
- 评分配置版本和历史版本入口；
- `.env` 缺失配置项的安全提示状态。

左侧“评分与分层、归档与保留、模型与摘要”只是静态标签，无对应画面或交互。对应 F10-7、AC-D14、AC-E13。

### P1-03：运行记录没有失败详情与阶段级重试闭环

当前页有运行列表、成功/部分失败/失败状态、最近一次成功运行阶段和日志，但“立即运行”和“详情”均无连线；失败记录未展示失败来源、阶段、原因、重试次数和可用操作。

还缺少：运行中、重复触发被拒绝、超时待补跑、遗留锁恢复、单阶段重试、飞书分段失败及仅补发失败分段等状态。

对应 AC-D12、AC-E01～E11。

### P1-04：回收站“永久删除”闭环成立，“恢复”闭环缺失

永久删除可进入二次确认，取消和确认均返回回收站，满足原型级二次确认要求。恢复按钮没有连线，也没有恢复成功状态，无法验证恢复原专题、版本、笔记及用户元数据。

对应 AC-I07、AC-I08。

### P1-05：今日首页的信息完整性与边界状态不足

已有任务状态、总数、三级数量、专题分布、来源构成、新增/更新和 7 日趋势。

缺口：

- 首屏专题分布只显示 3 个专题，未满足四个专题入口；
- 情报清单只有“必读、重要”示例，未体现“扩展”层级和按专题组织的后续内容；
- 缺少“今日无达标情报”；
- 缺少图表空数据和“数据不完整”状态；
- 缺少任务运行中、部分来源失败、待处理记录的可操作入口。

对应 AC-D01～D04、AC-F21。

### P1-06：搜索筛选有外观但无交互状态

历史检索页面已列出专题、层级、来源、标签、收藏、阅读状态、日期范围、最低分和排序条件，字段覆盖较好；但检索按钮、筛选器、排序器均无原型连线，也没有语义检索降级、无结果、加载、错误或筛选结果变化状态。

对应 F11 本地搜索、AC-F25。

### P1-07：用户元数据操作只展示，未证明状态变化

详情中的“保存备注、收藏、已读”均没有连线，“置顶”缺失。原型无法验证切换前后状态、保存成功、保存失败、跨版本保留等要求。

对应 AC-I02、AC-I03、AC-I05。

## 8. 已闭环与未闭环流程

### 已闭环

1. 今日/专题/检索列表 → 情报详情 → 关闭返回今日情报。
2. 情报详情 → 剔除原因确认 → 确认后进入回收站；取消返回详情。
3. 回收站 → 永久删除二次确认 → 确认或取消后返回回收站。
4. 8 个一级导航页面之间可互相跳转。

### 未闭环

1. 新增/编辑/暂停/恢复/删除信息源。
2. 专家白名单和 GitHub 发现规则管理。
3. 历史搜索、筛选、排序及无结果/降级状态。
4. 详情页来源、版本和双语内容标签切换。
5. 收藏、取消收藏、置顶、取消置顶、已读和笔记保存。
6. 扩展搜索、结果收藏、去重关联和正式归档。
7. 手动生成完整选题建议。
8. 质量反馈保存、评分校准建议、确认应用、版本回退、历史重新评分。
9. 失败运行详情、阶段级重试、超时补跑、飞书失败分段重推。
10. 回收站恢复及恢复结果。
11. 系统设置标签切换、保存、校验、配置缺失和服务状态查看。
12. 专题显示顺序调整及其对网页和飞书推送的影响确认。

## 9. 关键前端组件缺口

建议补齐以下可复用组件及必要状态：

| 组件 | 必要状态 |

| 来源证据表 | 来源名称、类型、链接、发布时间、可访问状态、观点、覆盖比例。 |

| 五维评分解释 | 总分、五维得分、判断依据、评分配置版本。 |
| 选题建议卡 | 标题、大纲、爆点、支撑来源、生成中、生成失败、重新生成。 |
| 扩展搜索结果卡 | 评分、来源、重复关联、收藏入库、临时结果标识。 |
| 评分校准建议卡 | 样本量、不确定性、维度变化、影响范围、接受/拒绝。 |
| 运行失败详情 | 来源、阶段、时间、原因、重试次数、阶段级重试。 |
| 配置状态卡 | 飞书/模型已配置、未配置、缺失项、连接测试结果。 |
| 通用状态 | 加载、空数据、数据不完整、失败、重试、禁用、保存成功/失败。 |

Figma 当前没有 Component、Component Set 或 Instance。建议在补页面前先建立最小组件集合，至少覆盖按钮、标签、情报行、表格操作、表单项、状态提示、抽屉和确认弹窗，避免后续 12 个以上状态画面产生样式漂移。

## 10. 建议的原型补全顺序

### Gate 1：统一产品契约

1. 确认四个一级专题最终口径；
2. 统一五维评分名称、权重和评分版本展示；
3. 明确“删除”在 UI 中统一称为“剔除”还是“移入回收站”。

### Gate 2：补齐三条核心价值链

1. 情报精读链：列表 → 详情正文 → 来源观点 → 历史版本 → 选题建议；
2. 扩展搜索链：发起 → 搜索中 → 结果 → 收藏 → 去重/关联 → 归档；
3. 质量校准链：反馈积累 → 发起校准 → 查看建议 → 确认/拒绝 → 新版本/回退。

### Gate 3：补齐后台运营链

1. 来源与专家 CRUD、GitHub 规则；
2. 运行失败详情、阶段重试、补跑和飞书重推；
3. 系统设置所有标签页、配置状态和保存校验；
4. 回收站恢复。

### Gate 4：补齐状态矩阵

为今日、检索、详情、运行、设置和扩展搜索至少补充加载、空、部分数据、失败、重试、处理中和成功反馈状态。

## 11. 再验收通过门槛

进入前端迭代开发前，建议至少满足：

- P0-01～P0-04 全部关闭；
- AC-D01～D12、D14 均有明确画面或可点击状态，D13 标记为实现期性能验收；
- AC-I01～I15 每项都有可演示路径或明确标注为实现期验证，不再以静态按钮代替交互；
- 来源配置、精读、扩展搜索、评分校准、运行重试、删除/恢复六条核心流程均能从起点走到成功、取消和失败分支；
- 建立最小 Figma 组件集和统一状态命名；
- 由产品方确认专题口径、评分维度、详情信息层级和关键危险操作文案。

## 12. 评审边界

本报告评审的是 Figma UI 覆盖度和原型交互，不将静态画面等同于后端能力已实现，也不对 AC-D13 性能指标、数据持久化、安全清洗、任务并发锁、日志脱敏及真实飞书/模型连接作通过判断。上述项目应在实现和联调阶段另行验收。
